## Phase 2: Virtual NIC & L2 Layer

### What was done

We implemented the packet I/O layer (reading/writing raw packets via Linux TUN/TAP devices) and the L2 Ethernet frame parser that sits on top of it.

### Concepts explained

**TUN/TAP** is a Linux kernel feature that creates virtual network interfaces:
- **TAP** operates at L2 (Ethernet frames) — this is what we use
- **TUN** operates at L3 (IP packets)

When you open `/dev/net/tun` and configure it as a TAP device, you get a file descriptor. Writing to it sends an Ethernet frame "into" the virtual interface. Reading from it receives frames that the kernel (or other programs) sent to that interface.

**Ethernet frame format:**
```
[Dst MAC: 6 bytes][Src MAC: 6 bytes][EtherType: 2 bytes][Payload: 46-1500 bytes]
```

EtherType tells us what's inside:
- `0x0800` = IPv4
- `0x0806` = ARP

### Files created

#### `src/ironstack/io/vnic.h` and `vnic.c` — Virtual NIC abstraction

Manages up to 8 virtual TAP interfaces. Each interface has:
- A name (e.g., "iron0")
- A MAC address (6 bytes)
- A file descriptor for reading/writing
- RX/TX/drop counters

Key functions:
- `vnic_init()` — initialize the subsystem
- `vnic_create(name, mac)` — create a TAP interface, returns index
- `vnic_read(idx, buf, len)` — read one frame (non-blocking)
- `vnic_write(idx, buf, len)` — write one frame
- `vnic_inject(idx, buf, len)` — same as write (for testing tools)
- `vnic_get(idx)` — get interface info

The TAP device is opened with `O_NONBLOCK` so `vnic_read()` returns immediately if no packet is available (returns -1 with errno=EAGAIN).

#### `src/ironstack/l2/eth.h` and `eth.c` — Ethernet frame handling

**eth_parse()** — Takes raw bytes and extracts:
- Pointer to the Ethernet header (dst_mac, src_mac, ethertype)
- Pointer to the payload (everything after the 14-byte header)
- Payload length
- Which interface it arrived on

Validation:
- Frame must be at least 14 bytes (ETH_HEADER_LEN)
- EtherType must be known (IPv4 or ARP), otherwise dropped

**eth_build()** — Constructs a frame from parts:
- Takes dst_mac, src_mac, ethertype, payload
- Writes the complete frame into an output buffer
- Returns total length, or -1 if too large (>1514 bytes)

**eth_dispatch()** — Routes the frame to the right L3 handler:
- EtherType 0x0800 → calls `ip_input()` (L3)
- EtherType 0x0806 → ARP (not yet implemented)
- Unknown → increment drop counter

### Pipeline integration

The main loop in `pipeline.c` now does:
```
for each interface:
    read a frame from the TAP device
    if frame received:
        parse it as Ethernet
        if valid:
            dispatch to L3
```

2. **Stubs in tests** — Unit tests include `eth.c` directly but provide a stub `ip_input()` function so they don't need the full L3 layer to compile.

3. **Module tests vs unit tests** — Unit tests are fast and silent (just PASS/FAIL). Module tests are verbose and show you exactly what the bytes look like, which is essential for understanding network protocols.

## Phase 3: L3 IP Layer

### What was done

We implemented the IP (Internet Protocol) layer which handles:
- Parsing and validating IP packet headers
- Deciding whether to deliver locally or forward to another interface
- Routing table with longest-prefix match
- TTL (Time To Live) management
- ICMP echo (ping) request and reply

### Concepts explained

**IP packet format (IPv4 header, 20 bytes minimum):**
```
Byte 0:    [Version(4 bits)][IHL(4 bits)]
Byte 1:    [Type of Service]
Bytes 2-3: [Total Length]
Bytes 4-5: [Identification]
Bytes 6-7: [Flags(3 bits)][Fragment Offset(13 bits)]
Byte 8:    [TTL]
Byte 9:    [Protocol]
Bytes 10-11: [Header Checksum]
Bytes 12-15: [Source IP Address]
Bytes 16-19: [Destination IP Address]
```

- **Version** = 4 (IPv4)
- **IHL** (Internet Header Length) = number of 32-bit words in header (minimum 5 = 20 bytes)
- **TTL** = decremented by 1 at each hop; packet dropped when it reaches 0 (prevents infinite loops)
- **Protocol** = what's inside (1=ICMP, 6=TCP, 17=UDP)
- **Checksum** = validates header integrity (recomputed after TTL change)

**Routing** — When a packet arrives, the stack must decide:
1. Is the destination IP one of our local addresses? → **Local deliver** (pass to TCP/UDP/ICMP)
2. Otherwise → **Forward** (look up route, send out another interface)
3. No route found → **Drop** (increment counter)

**Longest-prefix match** — If multiple routes match, the most specific one wins:
- `0.0.0.0/0` (default route) matches everything
- `10.0.1.0/24` matches 10.0.1.* (more specific)
- `10.0.1.100/32` matches only 10.0.1.100 (most specific)

**ICMP Echo (Ping):**
- Request: type=8, code=0, id, sequence number
- Reply: type=0, code=0, same id and sequence (just swap src/dst IP and change type)

### Files created

#### `src/ironstack/l3/ip.h` — IP header structure and API

Defines:
- `ip_header_t` — packed struct matching the wire format
- `ip_packet_t` — parsed packet with header pointer, payload pointer, lengths
- Helper inlines: `ip_get_version()`, `ip_get_ihl()`, `ip_get_header_len()`
- `ip_input()` — process an incoming IP packet
- `ip_output()` — build and send an IP packet

#### `src/ironstack/l3/ip.c` — IP processing implementation

**ip_input() flow:**
```
1. Validate: length >= 20 bytes
2. Validate: version == 4
3. Validate: IHL makes sense (header_len >= 20, <= packet length)
4. Validate: checksum is correct
5. Check: TTL > 0 (drop if zero)
6. Decision:
   - If dst_ip is local → deliver to ICMP/TCP/UDP handler
   - Otherwise → forward:
     a. Decrement TTL (drop if becomes 0)
     b. Recompute checksum
     c. Look up route
     d. Build L2 frame and send out interface
```

**ip_output() flow:**
```
1. Build IP header (version=4, IHL=5, TTL=64, protocol, src/dst)
2. Copy payload after header
3. Compute checksum
4. Look up route for destination
5. Build L2 frame and send
```

**Local address management:**
- `ip_add_local_addr(ip)` — register an IP as belonging to this stack
- `ip_is_local(ip)` — check if destination is ours

#### `src/ironstack/l3/route.h` and `route.c` — Routing table (FIB)

The routing table stores up to 128 entries. Each entry has:
- `prefix` — network address + prefix length (e.g., 10.0.1.0/24)
- `next_hop` — where to send the packet next
- `out_iface` — which virtual interface to use
- `hit_count` — how many times this route was used

**route_lookup()** algorithm:
```
for each active route:
    compute mask from prefix_len (e.g., /24 → 255.255.255.0)
    if (dst_ip & mask) == (route.prefix & mask):
        if this prefix_len > best so far:
            remember this route as best match
return best match (or -1 if none)
```

This is longest-prefix match — the most specific route always wins.

#### `src/ironstack/l3/icmp.h` and `icmp.c` — ICMP handler

**icmp_input() flow:**
```
1. Validate: packet >= 8 bytes (ICMP header size)
2. Validate: checksum is correct
3. If type == ECHO_REQUEST (8):
   a. Change type to ECHO_REPLY (0)
   b. Recompute checksum
   c. Call ip_output() with swapped src/dst
4. If type == ECHO_REPLY (0):
   a. Log it (for future ping tool)
```

### L2 → L3 connection

In `eth.c`, the dispatch function was updated:


So the full packet flow is now:
```
TAP device → vnic_read() → eth_parse() → eth_dispatch() → ip_input() → route/forward/local
```

## Phase 4: ACL & PBR Engines

### What was done

We implemented two packet filtering/routing engines:
- **PBR (Policy-Based Routing)** — overrides normal routing based on packet attributes
- **ACL (Access Control List)** — permits or denies packets based on match criteria

These are integrated into the IP forwarding path in **vendor-standard order**:

```
PBR (highest priority) → ACL (output filter) → FIB/Static Routing (fallback)
```

This means:
1. PBR is checked first — if a policy matches, it overrides the routing decision
2. ACL is applied on the output path — after the routing decision is made, ACL decides whether to permit or deny
3. FIB (static routing) is the fallback — only used if no PBR rule matches

### Concepts explained

**ACL (Access Control List)**

An ACL is an ordered list of rules. Each rule says "if a packet matches these criteria, PERMIT or DENY it." Rules are evaluated **top-down, first-match wins** — the first rule that matches determines the outcome.

```
Rule 1: PERMIT TCP dst-port 80    ← checked first
Rule 2: DENY TCP any              ← checked second
Default: DENY                      ← if nothing matches
```

A packet going to TCP port 80 hits Rule 1 (PERMIT). A packet going to TCP port 443 skips Rule 1, hits Rule 2 (DENY).

Match criteria:
- Source IP prefix (e.g., 10.0.1.0/24 or "any")
- Destination IP prefix
- Protocol (TCP, UDP, ICMP, or any)
- Source port range
- Destination port range

**PBR (Policy-Based Routing)**

Normal routing uses the FIB (Forwarding Information Base) which only looks at the destination IP. PBR can override this based on **source IP, destination IP, and protocol** — allowing you to send traffic from different sources through different paths.

Example: "All traffic from 10.0.1.0/24 should go through interface 1 instead of the normal route via interface 0."

**Why PBR has higher priority than ACL:**

In real network equipment (Cisco, Juniper), PBR is evaluated before ACL because:
- PBR decides the **path** (where the packet goes)
- ACL decides the **permission** (whether the packet is allowed on that path)

The packet must first know where it's going before you can decide if it's allowed there.

**Loop detection:**

PBR can accidentally create routing loops if misconfigured. The implementation tracks which next-hops a packet has already visited. If a PBR rule would send a packet to a hop it has already seen, the packet is dropped.

### Files created

#### `src/ironstack/l3/acl.h` — ACL interface

Defines:
- `acl_action_t` — PERMIT or DENY
- `acl_match_t` — match criteria (src/dst IP prefix, protocol, src/dst port range)
- `acl_rule_t` — a complete rule (ID, match, action, hit counter)
- `acl_default_policy_t` — what to do when no rule matches (PERMIT or DENY)

API:
- `acl_init(default_policy)` — initialize with default permit or deny
- `acl_add_rule(id, match, action)` — add a rule (appended to end = lowest priority)
- `acl_delete_rule(id)` — remove a rule
- `acl_evaluate(src_ip, dst_ip, protocol, src_port, dst_port)` — returns PERMIT or DENY
- `acl_dump()` — print all rules and hit counts

#### `src/ironstack/l3/acl.c` — ACL implementation

Key logic in `acl_evaluate()`:
```c
for each rule (top to bottom):
    if rule matches packet:
        increment hit counter
        if DENY: increment STAT_L3_DROPS_ACL
        return rule's action
// No rule matched:
return default policy
```

Matching uses `iron_ip_matches()` from utils.h for IP prefix comparison, and `port_matches()` for port range checking. A port range of {0, 0} means "any port."

#### `src/ironstack/l3/pbr.h` — PBR interface

Defines:
- `pbr_match_t` — match criteria (src/dst IP prefix, protocol)
- `pbr_action_t` — what to do (next_hop IP, output interface)
- `pbr_rule_t` — a complete rule (ID, match, action, hit counter)
- `pkt_context_t` — per-packet state tracking (ACL checked flag, hop history for loop detection)

API:
- `pbr_init()` — initialize
- `pbr_add_rule(id, match, action)` — add a PBR policy
- `pbr_delete_rule(id)` — remove a policy
- `pbr_lookup(src_ip, dst_ip, protocol, ctx, *next_hop, *out_iface)` — returns 0 if matched, -1 if no match, -2 if loop detected
- `pkt_context_init(ctx)` — initialize packet context
- `route_seen_hop(ctx, hop)` — check if hop was already visited

#### `src/ironstack/l3/pbr.c` — PBR implementation

Key logic in `pbr_lookup()`:
```c
// Invariant check
if (!ctx->acl_checked) → error (should not happen in vendor-standard order)

for each rule:
    if rule matches (src_ip, dst_ip, protocol):
        if next_hop already in hop_history → return -2 (LOOP)
        add next_hop to hop_history
        increment hit counter
        set *next_hop and *out_iface
        return 0 (matched)

return -1 (no match, fall through to FIB)
```

### Integration into IP forwarding path

In `ip.c`, the forwarding section now follows vendor-standard order:

```c
/* Step 1: PBR lookup (highest priority) */
int pbr_rc = pbr_lookup(src_ip, dst_ip, protocol, &ctx, &next_hop, &out_iface);

if (pbr_rc == -2) → drop (loop detected)

if (pbr_rc != 0) {
    /* Step 3: No PBR match, fall through to FIB (static routing) */
    if (route_lookup(dst_ip, &next_hop, &out_iface) != 0) → drop (no route)
}

/* Step 2: ACL check (applied on output path after routing decision) */
if (acl_evaluate(src_ip, dst_ip, protocol, sport, dport) == ACL_DENY) → drop
```

The full forwarding pipeline is now:
```
IP Validation → TTL decrement → PBR → ACL → FIB (fallback) → L2 TX
```

### Refactoring: shared helpers moved to utils.h

During this phase, `prefix_mask()` and `ip_matches()` were duplicated in route.c, acl.c, and pbr.c. When module tests included all .c files together, this caused redefinition errors.

Solution: moved to `common/utils.h` as shared inline functions:
- `iron_prefix_mask(prefix_len)` — compute subnet mask from prefix length
- `iron_ip_matches(ip, prefix_addr, prefix_len)` — check if IP belongs to a prefix

All three modules now use these shared helpers.
